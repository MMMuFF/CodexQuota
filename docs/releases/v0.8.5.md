# CodexQuota v0.8.5

## 中文

本版安装包为 0.8.5（34），首次包含签名自动更新器。旧版本用户需手动安装一次。

- 预计耗尽时间增加启动门槛：时间已过或额度已用任一达到 **15%** 后才开始估算。
- 两者都低于 15% 时显示“数据不足，暂不预测”，隐藏时间条上的预测竖线；实际时间和额度进度保持可见。
- 15% 门槛不使用界面四舍五入后的整数值判断，避免 14.99% 被提前视为达标。
- 切换到样本不足的新周期时，旧预测竖线立即隐藏。
- 同步中英文提示、悬停说明和 README。
- 构建 32 修复昵称边界失效时额度被压成零宽的问题：可靠边界用于动态定位，测量失败时沿用旧版固定左侧留白，并保留右侧按钮避让。该回退对特别长的昵称仍有限制。
- 悬停详情为日期增加星期，包含个人重置、预计用完、会员到期、券到期及公共公告；星期与日期一起跟随电脑时区，英文界面同步支持。构建 34 按用户反馈将默认吸附文案保持为“百分比 · 日期 · 剩余天数”，不显示星期。
- “···”菜单增加检查更新和自动更新开关，默认每天检查正式 Release。采用 Sparkle 2.10.0 验证签名清单与更新包，空闲时安装重启，不打断用券操作。首次仍需手动安装此版本；辅助功能权限可能需重新授予。见[签名更新指南](../automatic-updates.md)。
- 构建 34 修复检查更新误报“请等待当前操作完成”的问题：检查与下载可在刷新或查看详情时进行，仅安装阶段等待空闲。

达到门槛后仍按本周期平均消耗速度线性估算，仅供参考。零消耗、零已过时间或缺失周期数据等情况仍可能无法计算，不影响主额度与重置券功能。

验证覆盖 65 项核心检查、24 项 AppKit 检查及英文模式，包括 15% 门槛边界、默认文案保留天数、详情日期星期、忙碌期间检查更新及安装等待；Release 构建、App/ZIP 和更新清单签名校验通过。用户已确认构建 33 的日期和更新菜单可见；构建 34 的真实界面仍需用户复核。实际跨版本自动替换与重启仍待后续版本验收。

## English

The release bundle is 0.8.5 (34), the first version with a signed automatic updater. Older versions require one manual upgrade.

- Exhaustion forecasts start only when **either elapsed time or used quota reaches 15%**.
- Below both thresholds, show “Not enough data to forecast yet” and hide the forecast marker, while keeping actual progress visible.
- The threshold is checked before display rounding, so 14.99% does not qualify prematurely.
- Clear the previous marker when a new cycle has insufficient data.
- Update Chinese/English copy, hover help, and READMEs.
- Build 32 fixes zero-width overlays when nickname measurement fails. Reliable bounds enable dynamic placement; unavailable bounds use the legacy fixed left inset while preserving trailing-button spacing. The fallback still has limitations for unusually long nicknames.
- Hover details add local-time-zone weekdays to personal reset, exhaustion estimate, membership expiry, credit expiry, and public notice dates in both languages. Following user feedback, build 34 keeps the default sidebar text as “percentage · date · days remaining”, without a weekday.
- More now includes manual and automatic update controls. Sparkle 2.10.0 checks stable releases daily, verifies signed feeds/archives, and installs/relaunches when idle without interrupting credit use. The first updater-enabled version requires manual installation. Accessibility permission may need to be granted again. See the [maintainer guide](../automatic-updates.md).
- Build 34 fixes the incorrect “Wait for the current operation” update error. Checks and downloads can run during refreshes or while viewing details; only installation waits until idle.

Eligible forecasts remain linear estimates based on average usage this cycle, not guarantees. Zero usage, zero elapsed time, or missing cycle data can still prevent calculation. Main quota and reset-credit behavior are unchanged.

Validation covers 65 core checks, 24 AppKit checks, and English-mode checks, including the 15% threshold boundaries, days in the compact title, weekdays in details, checks while busy, and deferred installation. Release builds and app/archive/feed signatures passed. The user confirmed dates and update menus in build 33; the live build 34 UI still needs user review. End-to-end cross-version replacement and relaunch remain to be validated with a future version.
